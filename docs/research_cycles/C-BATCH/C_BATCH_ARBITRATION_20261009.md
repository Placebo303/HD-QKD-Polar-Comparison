### D5｜w_tail / Net_per_coin 分母不自洽 —— **成立，且仓内早有半显式记录**

[实测] 定义冲突：
- `C3_OPT_FINAL.md` **L9**：`w_tail=(C−B·N)/C（C=5M；映射行 C=B·N 故为 0）` —— C 取**规划值 5M**、B 固定 300。
- `C3_DESIGN.md` **L16–20**：`C_total` = 该工作点采集段内符合事件总数；`M = floor(C_total/N)`；
  `C_used = M·N`；`C_tail = C_total − C_used`。原规定 **B 即 M**，随 N 变化。

[派生] 主线程复算（F1-A3/4096）：
```
C_used = B·N = 300 × 4096 = 1,228,800
w_tail = (5,000,000 − 1,228,800) / 5,000,000 = 0.75424   ✓ 与表载 0.754 一致
Net_per_coin = 8,689,788 / 5,000,000        = 1.7380      ✓ 与表载 1.7380 一致
Net_per_used = 8,689,788 / 1,228,800        = 7.0718      （与 1.7380 相差 4.07×）
```
→ **`w_tail=0.754` 不是"N 造成的尾部浪费"，而是"5M 规划采集里只跑了 300 块"的采样比**。
按 `C3_DESIGN.md` L49–50 的本意（`分母用 C_total，故大 N 的 w_tail 自动拉低 Net_per_coin`），
尾部惩罚机制要求 **B=M 全跑**；M 波固定 B=300 使该惩罚机制失效并反向放大。

**仓内早有半显式记录**（[实测] `C3_MAPPED.md` **L7–8**）：
> "mini 的 Net_per_coin 用规划 5M 作分母，口径不同，不可直比"
→ 该不自洽在 mapped 表已被意识到，但未回灌到 `C3_OPT_FINAL` 主表。

**裁决**：`w_tail` 与 `Net_per_coin` 两列在复算前 **不进论文表**；只用 `Net_seg` + `Net_per_used`。
复算为纯派生算术（`c3_final.py` 重算满预算 `C_used` 分母版），分钟级，不跑解码器。

**核验加严（V2，比争议描述更严重，三条新证据）**：

1. **`Net_per_coin` 零 N 判别力**（[实测] 逐格校验 `mt_20261008/cells.json` 全部 31 格）：
   29 格满足 `Net_per_coin ≡ Net_seg/5e6`（仅 A4-SC/32768 两格因 `B·N=9,830,400>5M` 而
   `C_total=max(PLAN, B·N)` 例外）。→ 因 `C_total` 对全部 valid 格恒为 5M，
   **`Net_per_coin` 只是 `Net_seg` 的常数 1/5e6 缩放，退化为零信息**。
2. **`w_tail` 是 N 的冗余重述，不是实测量**：因 `C_total` 恒定，`w_tail` 成为 N 的严格单调函数
   （1024→0.939、2048→0.877、4096→0.754），**不携带任何独立信息**。
   设计语义下的真 `w_tail` 极小：M=floor(5e6/4096)=1220 → **0.000576**，与实际 0.754 差 **3 个数量级**。
3. **口径在代码层被显式写死且有注释**（非偶然）：`msd_c3_bakeoff.py:35-39`
   （`C_TOTAL_PLAN=5_000_000`）、`c3_report.py:6-7`（`Net_per_coin 一律 Net_seg/C_PLAN(5M)`）、
   `msd_c1_runner.py:102-109`、`msd_c3m_driver.py:730`。
   → 性质：**有意为之但从未与 `C3_DESIGN` §1.1–1.2 做 amendment 对齐的记账约定**。

**论文列用法（V2 建议，采纳）**：
- 译码器效率跨格可比 → 只用 **`Net_per_used`（÷C_used=B·N）**（唯一分母随格变化的列）
- 固定 5M 预算下的系统级产出 → 用 `Net_per_coin`，但 **`w_tail` 栏必须改名为
  「预算利用率 1−B·N/C_total」或「未用采集比例」，禁止称「尾部浪费/tail waste」**
- 跨 regime 对照（G-5/F-1/D-4）**必须**用 `Net_per_used`
  （`c3_mapped_derive.py:5-7` 已如此规定；实测 G-5 89,338,611/9.088 ≈ 300×32768 ✓）
- **主表 L20-34 的「Net/符合」栏头未标明用的是哪一列 → 跨表口径混用隐患**，须补注

**⚠ 核验新发现（D5 附带，独立缺陷）**：
- **β 栏口径与头注不符，差约 8×**：头注 L6 称 `I_op=H_A−H_AB=9.611`；而
