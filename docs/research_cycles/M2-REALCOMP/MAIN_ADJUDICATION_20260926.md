## Blocking findings

1. **Actual disclosure and displayed f disagree.** `m2real_runner.py` lines 247–255 compute `f_notag=5m/(1024 H_corr)` and `f_super=(5m+64)/(1024 H_corr)` for HDC and LB, irrespective of their `leak_EC`. Lines 786–801 separately sum the actual `leak_EC` into `lambda_parts`. At 1M, m=197, `rows.json` gives HDC `leak_EC=1,707,485` bits and LB `646,160` bits over 205 superframes. Dividing each by `205*1024*0.8012690084416184` gives **10.15137** and **3.84156** as diagnostic actual tagless ratios; `RESULT.md` §2 instead lists **1.20048829** for both. These diagnostic ratios are not accepted replacement results. The review's A-CMPE disclosure PASS missed this inconsistency.
2. **Tag scope disagrees.** The runner records 64 bits per 64-symbol block (`m2real_runner.py` lines 749–755, 786–801): 3,280 blocks at 1M mean 209,920 tag bits, or **1,024 bits per 1024-symbol superframe**. The displayed `f_super` adds only 64 bits per superframe. The M0/V80 frozen comparison basis uses a 64-bit tag per superframe. Whether the new methods really verify each small block or only the assembled superframe must be specified before a corrected comparison; neither total may silently stand in for the other. On the recorded 16-tag accounting, the same 1M/m197 diagnostic inclusive ratios are **11.39939** (HDC) and **5.08958** (LB).
3. **`f_eff` and FER use incompatible scales.** M2 reports 64-block FER, while `f_eff=f_super+4.785675*FER` imports the NB 1024-symbol superframe slope. It is not a validated method-specific efficiency for these 64-block protocols. The superframe success columns are all zero; keep block and superframe denominators distinct.
4. **D2 was not evaluated by its frozen rule.** The rule says LB `f` better or equal to NB triggers branch (2); using the displayed same-m `f_notag`, equality holds mechanically. The first review instead rejects branch (2) because LB FER is poor, adding an unstated condition, and declares branch (3). Since the displayed f is itself not actual disclosure, no D2 branch can be accepted from that worksheet. Any revised rule or comparison metric requires a new preregistration before claim-bearing evaluation.
5. **Method identity remains limited.** HDC uses `assumed-v1` Gray/block/pass parameters rather than a source-verified Müller implementation (`PREREG_AND_AUTH.md` §1). The real LB outputs do not record `backend_used`, and the adapter can use either SPA or a numpy min-sum fallback (`m2real_runner.py` lines 857–881). The synthetic LB batch documented min-sum fallback, but that does not prove the real run's backend. The present data describe these implementations only, not a ranking of the named method families.
