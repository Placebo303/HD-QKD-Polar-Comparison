## 1. 核心异议：这张地图是在"戴眼罩"状态下测绘的

备忘录封死的所有格子——码率 edge 92|96、固定点 0–1/128、自适应 87→79、
解码四杀、缩放地板+天花板、先验三级小步——**全部是在同一个生产先验
`p_f` 下测的**，而这个先验是被 λ 平滑抹平的 Bob 盲分布：

```
P(a|b) = (counts[a,b] + λ·p_global[a]) / (n_b[b] + λ),  λ = 137.38
```

- 1024×1024 表 / 262,144 样本（每 Bob 列 ≈256、每格 0.25 样本）⇒ 平滑占
  **34.9%** 且投向 Bob 无关的全局边际 ⇒ 每符号条件熵 ≈ **4.343 bits**
  （GF(32) 上限 5，实测 belief_mean_entropy 上界 4.343407）；
- 这不是"数据脏"：V25 在同一类数据上实测 delta 模型 holdout NLL
  **0.81–0.83 bits**、V19 实测 `H_full = 0.549955`；二元 MLC 用
  587 bits/帧（≈2.29 bits/符号）在 500 plane-frame 上 **0 失败**。

**地图上的每个数字都是 `L2 @ H_eff≈4.34` 的属性，不是 `L2` 的属性。**

## 2. "差一个量级"的算术分解——缺的恰好是先验里被抹掉的信息

备忘录：回正需 ≈115+ 低阶段接受，"差一个量级，不差一口气"。

- 当前 `H_eff = 4.343` ⇒ 容量下界 `m ≥ (128×4.343+64)/5 ≈ 111`，
  而净正需 `m ≤ 39`（`N = 320 − 8m`）。**这是 3× 的容量缺口，任何解码
  机制都跨不过去**：m=39 时 syndrome 只有 259 bits，错误模式带 ~556 bits
  不确定性，平均每个 syndrome 撞 ~2^297 个候选——list/min-sum/trapping-set
  都无法把真值排到前面。
- 若 `H_eff → 0.8`（V25/V19 锚点）⇒ `m ≈ 25–31`，净 **+72…+120 bits/帧**。
- 两个世界的泄漏差：`5×(111−28) ≈ 435 bits/块 ≈ (4.343−0.8)×128`。
  **"差的那个量级"在数值上恰好等于先验里被 λ 抹掉的 3.5 bits/符号。**

## 3. 对备忘录三条"活路"的评估

### ① S0 新机制（list/猜测/trapping-set/归一化 min-sum）

- 在 `H_eff≈4.34` 下**数学上不可能回正**（见 §2 容量论证）。此时做机制
  研发是在容量下界面前优化解码器——期望收益严格为 0，与备忘录自己的判断
  一致（"L2 再烧轮次期望收益≈0"），但**原因不是机制穷尽，是信息没到位**。
- 机制研发只有在 `H_eff ≤ 1.0` 之后才有意义：那时剩余差距是 1.2–1.5×
  的有限长/解码效率问题，恰好是 list/min-sum 的用武之地。
- **顺序反了：先修信息，再修机制。**

### ② n=1024 真实

同意封存，且可加公式支撑：通式 `N = n[5Â − (1+Â)H_eff] − 64(1+Â)`，
`H_eff > 1.875` 时**任意 n 都渐近为负**。在 4.34 下开 n=1024 不是赌博，
是确定亏。

### ③ 跳出 L2（L1/跨层/Cascade）

- L1/跨线与④共享同一个根：**跨层本质就是条件化**（L2 条件于 U1）。
  若先验修复成立，"L2"与"跨层"大部分合并；若不成立，跨层同样被
  H_eff 压死。跨线侦察在 S0 之前无法给出不同答案。
- **Cascade 被系统性低估**，且是 G7 verdict 明确"未测"的邻线。结构性理由：
  G6/G7 块权重散布 51–123/128，固定码率码必须按尾部付泄漏（这正是
  自适应分级 m120 只能到 79/128 的原因）；Cascade/交互式的泄漏
  **自适应于实际错误数**，天然吃这个散布。本仓库 `cascade_formal_v1`
  已有 promoted 先例（另一域）。若 S0 证伪我先验论，Cascade 应升格为
  ③ 内的首选，而不是并列项。

## 4. 备选方案（备忘录选项之外的）

### ④ 修先验（S0 → F1/F3）——成本最低、证据最直接的活路

- **S0**：只读冻结产物 `counts_ab`（1M CAL）算结构化先验（δ 位移模型）
  的每符号熵 `H_B`。**秒级、零真实数据、零解码器调用、EXPLORE**。
- 判据（已冻结，见 `PREREG_AND_AUTH.md`）：
  `H_B ≤ 1.023` → L2 未死，进 DE 复扫（预期 edge 从 92|96 大幅下移，
  这同时改写备忘录的"回正数学"）；
  `H_B > 1.875` → 我方根因论被证伪，备忘录封死成立，转 ③（Cascade 首选）。
- 已知风险（诚实声明）：V25 的 0.55–0.83 锚点是 1M session；G6/G7 池含
  1p5M/2M，δ 分布可能随 session 漂移 ⇒ 完整修复需 per-session counts
  （F3，需真实数据授权，DECIDE）。S0 只能在 1M 上裁决机制成立与否。

### ⑤ 若 S0 证伪：先对齐/条件化，再纠错

若 `H_B` 仍高，说明池子的误差不是 δ 结构（或分帧时结构已被丢弃）。
那么正确动作不是换码族，而是**在纠错前恢复条件结构**（delay/±1 对齐，
V25 M0 已给出方向与数据），然后再谈 L2/Cascade/二元。这与"换更安静数据"
不同——同一份数据，不同的表示。

## 5. 对"先验三级/λ/F1/条件化已封死"的逐项质询

这些格子被封死前，**必须出示过下面两个数字之一**，否则封印无效：

1. 结构化（Bob 全符号条件化）先验的**每符号条件熵实测值**；
2. 锐化先验下的 **DE 边沿**（是否离开 92|96）。

已知证据的反向暗示：

- R2DIAG A1（uniform）vs A2（model_f）**零对比**——因为 model_f 本身
  ≈均匀（4.343/5）。"prior not binding"只在近均匀先验族内部成立，
  不能外推到结构化条件先验；
- "先验三级 0→1→2 小步"——若三级都在近均匀族内（边际/会话边际/微调 λ），
  小步是根因论的**预言**，不是反驳；
- λ 重调封死——非参 1024×1024 表在 0.25 样本/格下**不可辨识**，封死的
  应是"表+全局回退"这个模型类，不是"条件先验"这个方向；
- F1 若指 `METHOD.md` 的 δ 位移模型且只测了端到端 FER——端到端失败不能
  区分"先验不够锐"与"接线错误"（如只换采样器没换解码器先验、或用在
  跨 session 池上）。**要的是 H_B 这个数。**

## 6. 结论与建议决策

**A/B/C 都不是第一步。第一步是 S0（几分钟、零成本、零风险）。**

- S0 `H_B ≤ 1.023` → L2 复活：F1/F3 + DE 复扫；机制研发（①）排在其后
  解决 1.2–1.5× 有限长差距。备忘录的地图需要重绘。
- S0 `H_B > 1.875` → 根因论证伪，备忘录封死成立：选 ③，且 Cascade
  升格首选（自适应泄漏 vs 固定码率在高权重散布下的结构性优势）；
  ① 在容量下界面前无意义，不做。
- 中间区间（`1.023 < H_B ≤ 1.875`）→ n=1024/更大 n 与先验修复组合，
  单列决策。

若其他 session 已测过 `H_B` 或锐化先验下的 DE 边沿，**请直接出示数值**，
它取代以上全部分析作为裁决。

## 8. 裁决与修正（2026-09-19 晚，实测数送达后）

### 8.1 证伪接受

- **`H_B`（最差面）= 3.6925 > 1.875** ⇒ §6 证伪分支触发。本简报的根因论
  （"3.5 bits 可回收"）被实测否定：shift 先验只回收 **0.65 bits**
  （uniform 5 → modelF 4.34 → shift 3.69），R18/R19 条件化 +0.02，
  v49 查 V25 线无新数。**单平面 L2 路线的封死成立。**
- 一致性验证（值得记录）：`m_min = 128×3.69/5 = 94.5`，与实测 DE 边沿
  **92|96** 吻合——测得的熵就是那条边沿的熵。测量闭环。
- 接受 corrigendum：§2 的 `m≤39 / 2^297 / N=320−8m` 继承 R14 的 k-based
  口径（R16 已撤）。以下门槛全部改用 **n-based** 口径重算。

### 8.2 同一个数也杀死了"Cascade-on-U2"——R25b 不要按原样发

§6 的"Cascade 首选"是在 `H_B` 不存在时写的，理由是"固定码率按尾部付泄漏"。
`H_B=3.69` 出来后，该理由失效：**交互式自适应只能压 overhead 系数 f
（1.3–1.5 → 1.05–1.1），压不动平均熵**。单平面 n-based 门槛：

```
N = 384 − (5m + 64) > 0 ⟺ m ≤ 63；容量 m ≈ 25.6·H ⟹ 可行 ⟺ H < 2.5/f
H = 3.69 ⇒ 容量处净 = 128×(3.0 − 3.69) ≈ −88 bits/块（理想），
f=1.05–1.1 ⇒ ≈ −112…−135。Cascade-on-U2 在跑之前就已算死。
```

### 8.3 还剩两个未被信息论排除的框架（判据：你们已有的逐面熵表）

单平面封死 ≠ 整个池子封死。同一张逐面条件熵表可以直接裁决两个框架：

**(J) 联合 L1+L2 / 全符号（10 bits）**

```
N = 768 − (f·128·H_full + 64) > 0 ⟺ H_full < 5.5/f
   （f=1.1 → 5.0；f=1.05 → 5.24）
H_full = H(U2|B) + H(U1|B,U2) = 3.69 + h₁|₂
⟹ 需 h(U1|B,U2) < 约 1.3–1.55 bits
```

- 若过：整个路线的定性改变——不是"L2 亏损"，是"**L1+L2 作为一对盈利**"，
  L2 是亏损领头羊。且码设计从当前死亡区（有效率 ~0.06）移到 **rate ≈
  0.45–0.55** 的常规 LDPC/二元 MLC 舒适区（v4/v5 机器就住那里）。
- 注意 R14 的 U1/U2 权重只差 ~4%（69.8 vs 72.7）——是**权重**不是条件熵，
  `h(U1|B,U2)` 完全可能远低于 U2 的 3.69（时间戳抖动打低位）。

**(S) 选择性 Gray 位面（binary，逐面裁决）**

```
位面 i 单独盈利 ⟺ h_i < 0.6/f ≈ 0.55 bits
净 = Σ_选中 (76.8 − f·128·h_i)；未选中位面不付泄漏也不产密钥（合法）
```

- 二元 MLC 证据（V17 逐位面 BER≈3.8%）暗示位面熵高度偏斜——在 V17 数据上。
  G6 池的逐位面分布由这张表直接给出。

### 8.4 修正后的决策建议

对"继续 Cascade（重发 R25b）/ 改道 / 收兵"的回答：**三者都不是现在**。
先做一次零成本裁决（读你们已有的逐面熵表 + 算 H_full）：

- **(J) 过**（h₁|₂ < ~1.3）→ R25b 改写到联合框架再发（码族其次，框架才是
  决策；Cascade 的逐帧自适应在联合框架下因 H_full 逐帧波动而真正有用）；
- **(S) 有 ≥3 个 h_i < 0.55 的位面** → 选择性位面框架，走二元 MLC 机器；
- **两者都不过** → **收兵**。终局是信息论性的：该池类在任何码族、任何
  解码器、任何调度下都不可净正（Cascade 亦然，见 §8.2），决策权升级到
  采集层面（更安静窗口/参数），不再是算法问题。届时 ①/②/③ 全部
  无需再烧轮次——这与备忘录的判断一致，但理由从"格子测完"升级为
  "信息论封顶"。

## 10. 历史成功与本次终局的关系（回应"之前成功过，为什么现在停"）

### 10.1 两个历史成功各自"成功"的是什么

| 结果 | 数据类 | H(A\|B) | 纠错 | 效率 f | 每符号泄漏 vs 毛密钥(Â·10=6) | 净 |
|---|---|---|---|---|---|---|
| NB-LDPC R3（V13-R3 legacy audit，真实数据） | 2026-01-21 三源 | ≈0.80 | **8284/8412 exact（98.5%）** | **≈12.1** | 12.1×0.80=9.7 bits | **≈−3.7 bits/符号** |
| Binary LDPC MLC（V19 原型，V17 逐位面信道） | Jan-21/V17 类 | ≈0.55 | **500/500 plane-frame 0 失败** | ≈4.17 | 4.17×0.55=2.29 bits | **+3.7 bits/符号** |

- **R3 是纠错成功，从来不是密钥成功**：f≈12.1 意味着泄漏 9.7 bits/符号，
  几乎等于符号全部 10 bits——"适用性不够"指的就是这个。合成线的
  V3/V4/V5 也全是"差一帧"的纠错近失（127–128/128），从未有过效率达标。
- **Binary 是唯一的效率成功——但在安静数据上**（H≈0.55）。

### 10.2 项目目标升过一级

早期目标：**纠得对**（FER/exact）。当前目标：**净密钥为正**
（`净 = Â·10 − f·H − tag > 0`，即 `H < 10Â/f`）。在旧目标下没有任何东西
被停止——R3 式纠错今天仍然可用。终局只约束新目标。

### 10.3 数据类换了，门没换：同一把尺子量两个池类

门槛 `H_full < 10Â/f`（Â=0.6）：

| | Jan-21 类（历史成功所在） | Jan-23 池类（G6/G7 所在） |
|---|---|---|
| H_full（实测） | ≈0.55–0.80 | ≈5.08+（raw 乐观，真值只高不低） |
| f=1.1 时净 | 6−0.88=**+5.1 bits/符号** | 6−5.59=**−0.4（叠 tag 更差）** |
| f=1.3（D/G 系列原目标） | 6−1.04=**+5.0** | 6−6.60=**−0.6（≈−77 bits/帧）** |

1. **即使 D/G 系列当初的目标（f≤1.3）完全达成，在 Jan-23 池上仍是每帧

2. **把历史上成功的 binary LDPC 原封搬到 Jan-23 池：−15.2 bits/符号**，
   比我们实测过的任何配置惨 3 倍。方法没有变差，数据变了（≈6–9×）。
3. 反之，**同一套机制在 Jan-21 类上全部净正**——包括尚未达成的 f≤1.3
   （+5.0 bits/符号 ≈ +640 bits/帧，是 binary 现状的 1.35×）。

### 10.4 结论：停止的范围与解除条件
