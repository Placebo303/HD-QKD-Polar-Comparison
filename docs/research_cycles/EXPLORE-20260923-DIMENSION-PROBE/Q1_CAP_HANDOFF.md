## 1. 必须改写的第一处：「确定性声明」

### 为什么错

裁决草案写：

> 在冻结 (K1,K2,N) 下本通道为常数 34,119 bits/block（现有 84 行全部相同）；
> 本 cap 认证的是"冻结 K 对冻结熵预算的关系"，**不提供、也不声称提供逐 block
> 甄别能力**。

在新前提下"84 行全部相同"不再自动成立：三臂若各有自己的 `K`，披露
`5·(K_arm1+K_arm2)+64`、`5·(K_arm3)+64` … 逐臂不同，cap 比较**从恒通过的
冗余断言变成真正会咬人的门**。若仍把"零甄别能力"的免责声明冻结进去，会出现
spec 自我矛盾：PASS 的文字说不甄别，而结构上其实在甄别。评审时必被打回。

### 替换文本（可直接粘）

```
**披露通道的确定性声明（预注册）。**
EC 披露通道的形式为 key_dependent_bits = 5·(K_a + K_b) + 64 bits/block，其中
K_a、K_b 为各臂冻结的 GF(32) 校验符号数（见 §Per-arm K）。在冻结 (K_a, K_b, N)
下，该通道对本臂的每一个 block 取同一个常数，等于 5·(K_a+K_b)+64。
因此 cap 比较是**逐臂**的一次确定性比较：
· 若某臂的 5·(K_a+K_b)+64 > cap，则该臂在第一次比较即判 over-cap，
  并触发 R2 packet 预注册的处置规则（§Over-cap 处置）；
· 若 ≤ cap，则该臂判 under/at，此结果是对"该臂的冻结 K 对冻结熵预算的关系"
  的认证，**不对任何 block 的译码正确性、FBER 或 FER 作任何陈述**。
本 cap 只认证披露率前提；它是否具有逐 block 甄别力，取决于各臂 K 是否互异，
由 §Per-arm K 的冻结值唯一决定，spec 不预先断言。
```

## 2. 必须补齐的第二处：Per-arm K 与 over-cap 处置（原裁决未覆盖）

裁决在旧前提下只需一对 `(K1, K2) = (319, 6492)`。新前提有三臂，需新增：

```
**§ Per-arm K（预注册，Phase A 冻结）。**
arm ∈ {A1, A2, A3}（名称按兄弟 Stage-3 冻结件）。每臂冻结一对 GF(32) 校验符号数
(K^a_a, K^b_a)，满足 K^a_a + K^b_a = K_total（D4 冻结的 K_total），
且每臂的披露 5·(K^a_a+K^b_a)+64 ≤ cap = 34794 bits/block。
冻结值须与 42/per-stage 的 tag recount 记录（1,432,998 = 34,119 × 42）一致；
若某臂的 K 拆分未冻结，该臂不得进入 Phase B。

**§ Over-cap 处置（预注册）。**
任一批次比较中出现 over-cap 时：只报计数，不写判定形容词；按 stage 与 pooled
双表报告；STOP 并按 blocker 上报，**不得**以修改 cap、修改 K 拆分、修改 f 或
修改 N 迁就数据。任何改动复现为一次 OpenSpec 变更 + 新 freeze。
```

### 冻结前需要兄弟确认的唯一决策（给方向即可）

| 问题 | 选项 | 对 cap 的影响 |
|---|---|---|
| 三臂的 K 是否互异？ | (a) 三臂共享同一 K 拆分 | 则 §1 的"逐臂"改为"单一比较"，文本相应简化；cap 判别力仍是"对 K_total"而非逐 block |
| | (b) 三臂各自 K 拆分 | 则按 §1/§2 原文冻结；cap 逐臂各咬一次，over-cap 归因到具体臂 |
| | (c) 其中一臂 K 未定 | 该臂不得进 Phase B，spec 明示 |

**建议 (b)**：Stage-3 三臂的目的正是比较不同构造/工作点，K 互异才使 cap 的
逐臂咬合真正产出信息；且 cap 一旦在 Phase A 被冻结，K 若随后浮动就等于
事后移动门柱。

## 3. 裁决自列的三条未封闭口子（照抄移交，优先级如序）

1. **H 的不确定性 1:1 传进 cap**：`d(cap)/dH = 1.3·N = 42,598.4 bits`。
   H 高估 0.01 吃掉 675 bits 余量的 63.1%。而 `H_M2` 是 32-frame CAL 三元组
   导出的经验条件熵。cap 认证的是"对冻结模型熵的率"，不是"对真值的率"。
   唯一化疗是 G2/G3 的 FER 门（独立机制），Stage-3 不提供第二道保险。
   **冻结时须连同 `H` 的标定帧数一起写进 spec。**
2. **public-control 通道不界**：`10·N + 63 = 327,743 bits/block` 的 λ_total
   成员资格是 SECURITY_MODEL 公开问题。Stage-3 PASS ≠ 全部披露在预算内。
   R3 效率门前必须关闭它，且关闭方式（新 cap / 新分解）是新 freeze。
3. **f 余量只容 FER ≈ 0.0053**（若采用本仓同族斜率 4.785675）：
   `0.0252192 / 4.785675 = 0.005270`。而 G2/G3 arm B 的 verify_failed 为
   3/14 与 6/14。verify_failed（检出拒绝）与 FER 的定义关系必须在 R2 packet
   内先行冻结，否则 Stage-3 的率认证会被过度读成"效率已认证"。

## 4. 另外两条本仓 reviewer 给兄弟的非阻塞修正（建议一并带走）

1. **双门**：最终包应冻结
   `N ≥ max(3/FER_target, ceil(3·4.785675/(1.3 − f_super)))`。
   `1000` 只覆盖精度门；在 A208 类紧余量工作点上认证门需 ≈2842。
2. **成本换算**：`1000 blocks × 3 臂 @ 20.36 s/block ≈ 17 h`（单核 wall）。
   原述 "5–6 小时" 只有两种成立读法：三路并行（未声明）或 1000 为三臂合计
   （每臂 N≈333 ⇒ `3/333 ≈ 0.9%`，与 0.003 目标自相矛盾）。

## 5. 一句话收口

Q1 裁决选 A 可以直接采纳，公式与常数集本仓复算无误；但**在兄弟确认
"三臂 K 是否互异"并按下文 §1/§2 替换文本改写两处之前，不应进入 Phase A
冻结**——否则会冻结进一段与新解码前提矛盾的免责声明，以及一处完全没被
覆盖的 per-arm K 冻结缺口。
