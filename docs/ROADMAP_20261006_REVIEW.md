## 2. 对用户问题「任意 2 幂次维度、任意 bw、不错的效率还差多少」的回答
- **前提更正（用户指出，2026-10-06）**：d 和 bw 都是用户在后处理中选择的分帧参数，**不是**采集的物理属性。
  同一段事件流可以按任意 (d, bw) 重新分帧；(1024, 200) 只是当前选定的工作点。
  由此推出三点：
  1. 28 格点不需要新的采集，但各格点用的是同一批事件，彼此**不是**独立样本；
  2. 「干净 OOS」只取决于**原始事件是否被用过**，与 (d, bw) 无关；
  3. plug-in 联合表的格数随 d² 增长（d=1024 约 100 万格），而平移不变的差分先验参数量只随 d 增长。
     所以 S-2 的稳健先验对大 d 尤其关键，这也是「任意维度」能否成立的前提。
- 目前 **28 格中 0 格**在真实数据上有完整符号可用的结果，当前工作点 (1024, 200) 也包括在内。
- 差距不在格点覆盖，而在两个基础问题：**完整符号口径**（u1 层），以及**先验对估计误差的稳健性**。
- 这两个问题在 (1024, 200) 上解决之前，扫格点只会把同一个失败复制 28 遍。

## 4. 新增硬规则（对 R1–R9 的补充）
- **R10 合成必须带失配**：任何合成结论若要传递到真实数据，信道与先验必须来自不同样本（或不同模型）。
  genie 先验的结果只能标「上界/乐观」，不得作为真实运行的冻结依据。
- **R11 完整符号口径**：成功、FER、f 一律按完整符号（所有层）计算；分层口径只作诊断列。
  任何「可部署」「占优」措辞都必须基于完整符号口径。
- **R12 深度优先**：在一个格点获得真实完整符号可用结果（G-1）之前，不立项多格点扫描，也不组装论文包。
- **R13 审查必查项**：Pre-RESULT 必须核对「成功」字段的语义覆盖了哪些层；只要有任何未纠正层的残错计数非零，就判 FAIL。
