# P 批审查 + 下一步（2026-10-06）

> 文档类别：documentation-only，不授权任何执行。上位：R1–R14。
> 依据：`EXPLORATION_LOG.md` 中 P-a 到 P-d 的条目（包括第 352、355、379、550 行）。

## 1. 审查结论

### 1.1 成立的部分
- P-a：先验质量用对数损失衡量，结果未饱和（0.954 → 0.798 bits/符号）。
- P-b：信道在分桶层面**平移不变**（KL 约 1e-4 nats）；偏移是亚 bin 的。
- T2-1M 与另两源在差分空间里形状确实不同，三源不能合并；1.5M 与 2M 可以合并。
- P-d：2026.1.23 的 0 dB 段（26.6 万对，SER 0.248）可用作干净 OOS。
- 个位数的失败计数已正确标注为「未定」，R1 得到遵守。

### 1.2 关键问题：S-2、P-b、P-c 的阴性结论都建立在同一个有偏代理上
- S-1 bootstrap 代理的「真信道」是 TRAIN-a 的**稀疏经验直方图**：它只能产生 TRAIN-a 里出现过的 (a, b) 对，并且带有抽样造成的尖峰。
- 在这种代理里：
  - 和它共享支撑集的 plug-in 先验天然占优；
  - 任何平滑先验，包括 P-b 证实为物理上正确的平移不变差分模型，都会被系统性地惩罚。
- 日志第 550 行的结论「零格是承重的（load-bearing）」，正是这种代理偏差的典型表现。
  在真实数据上，零格恰恰是**有害**的：MSD 真实 52/52 失败的机制就是落入零格。
- G-0 只验证了这个代理对 **plug-in 先验配置**的保真度，从未验证它能否公正地评价平滑先验。
- 因此以下结论只能在 bootstrap 代理范围内成立，不能推广到真实信道：
  - S-2「平滑先验全部失败」；
  - P-b「没有新的赢家」；
  - P-c「d=512/256 也全部失败」。
  - P-c 另有一个独立疑点：日志写着失败面未定位，并且没有说明在合并 bin 之后，各面码率是否按新的熵重新分配过。

### 1.3 一个未解的矛盾，需要先查清
- 信道平移不变（P-b）。如果是这样，用 31.5 万对估计的差分模型（约 2k 个参数）应当很密，零击中也少，至少不会比 plug-in 差太多。
- 但日志第 352 行记录差分模型的 held-out 对数似然比 plug-in 差。
- 可能的原因有三种，需要逐一排除：
  1. 平滑项（α）把概率质量撒到了物理上不可能的格（比如符合窗之外）；
  2. 先验没有乘上 A 的边际分布 P(a)，或者差分的方向、边界处理有误；
  3. 差分模型在 MSD 的逐面条件化路径中实现有误。

## 2. 下一步（按序，EXPLORE；只有 D-4 需要授权）

### D-1 genie-差分自检（纯合成，零真实数据）
- 信道直接由差分模型 g 生成，译码先验也用 g（genie-差分）。MSD 和 NB 都应在接近 H_g 的码率下成功。
- 如果失败，就是差分先验路径有实现缺陷：修好之前，**所有涉及平滑先验的阴性结论一律作废**。

### D-2 差分先验的对数损失对账（零解码，只用 TRAIN）
- 在 TRAIN 内做交叉验证，对比以下候选的 held-out 对数损失和零击中率：
  - 未平滑、限定在符合窗内的经验差分 g；
  - g × P(a)；
  - plug-in 加下限。
- 解释第 352 行的结果，确认差分模型到底输在哪里。

### D-3 物理代理（替代 bootstrap 代理）
- 信道改用平移不变差分模型（由 TRAIN-a 拟合，可选加少量结构噪声），先验由 TRAIN-b 估计。
- 用 G-0 的靶子校验：plug-in 先验在这个代理上应当复现真实的失败模式（零格失败、u2 FER 约 3–5%）。
- 校验通过后，用它重新评估平滑先验（MSD 与 NB），以及 P-c 的 (512, 400)、(256, 800)（合并 bin 后按新的熵重新分配码率），全部用 B ≥ 300。

### D-4 干净 OOS 仲裁（DECIDE，需用户确认）
- D-1 到 D-3 选出的最佳先验与 plug-in 对照，在 2026.1.23 的 0 dB 段上跑 NB 完整符号链，必要时加 MSD。
- 先验只用 R1 数据训练；0 dB 段只作测试。若其信道形状与 R1 训练源都不同，预先登记该偏差。
- 这是第一个**干净 OOS** 的真实结果，可信度高于 R1 上的任何再检验。
