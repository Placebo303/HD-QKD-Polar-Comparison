## 1. 审查结论

### 1.1 结果
- 第一个诚实的**真实完整符号**数字（S-5，已用数据上的再检验）：NB 链 f = **1.915 / 1.787 / 1.647**
  （T2-1M / 1.5M / 2M；FER 3.4% / 2.8% / 1.6%；undetected 0）。G-1（f ≤ 1.40）未通过，已如实分项记录。
- u1 层按链式条件重做后约 50 bit/超帧（原来 1419 bit）。S-1 代理的预测与真实一致或偏保守。
- 流程健康：三次错误（E4 重犯、最优点误选、f 单位 bug）都在审查中被抓住并修正，失败都保留了。

### 1.2 f 分解（推导）
以 `E_L ≈ 1193 bit` 加 tag 64 bit、`N·H(A|B)` = 817 / 845 / 851 bit 计算：

| 源 | 名义部分（零失败时的 f） | FER 惩罚部分 | 合计 |
|---|---|---|---|
| T2-1M | 1.54 | 0.38 | 1.915 |
| T2-1.5M | 1.49 | 0.30 | 1.787 |
| T2-2M | 1.48 | 0.17 | 1.647 |

要点：
- **即使 FER 降到 0，名义部分也已高于 1.40。** 所以只靠降 FER 过不了 G-1，必须同时降低披露量。
- 披露变大的原因是**先验失配**：genie 先验的合成 NB 在 m ≈ 200–208 时 f ≈ 1.26–1.39；
  换成真实先验后，m 必须提高到 224 才压得住 FER（约多 120 bit，约 +0.14 f），而且 FER 仍有 2–3%。
- 结论：**先验质量是当前最大的单一杠杆**，它同时决定名义部分和 FER 惩罚。MSD 卡住也是同一个原因。

### 1.3 遗留问题
- **U-4 辅线没有做**：已存的其他采集还没有做只读盘点，干净 OOS 臂仍为空。R1 的 VAL/HOLD 已被用过三次，
  后续真实运行的可信度会越来越依赖辅线。
- `_real_one` 的 `rok_u2` 只读取 `outs[0]` 这一缺陷，下次真实运行前必须修复（S5_RESULT 已登记）。
- 同数据 Polar 对照仍然缺失（已登记，不阻塞）。

## 3. 下一阶段 T 系列（先验优先）

### T-0 收尾（实现 + 只读）
- 修复 `rok_u2` 只读取 `outs[0]` 的问题。
- **U-4 辅线只读盘点**：列出所有已存采集。每段写明是否进入过任何译码或诊断，以及 SER、事件率、
  与 R1 三源信道的可比性；适用判据在盘点前写死。只读元数据和摘要，不解码。

### T-1 先验数据量曲线（EXPLORE，S-1 代理）
- 固定 NB 链，只改变先验的训练数据量（如 1/4、1/2、1、2、3 倍 TRAIN）。
  2–3 倍要靠跨源合并，或者在代理里用更大的 TRAIN 子集来模拟。
- 产出：FER、所需 m、完整符号 f 随训练量的曲线。
- 回答的问题：多给先验数据能省多少 f，判断 T-2/T-3 值不值得做。

### T-2 跨源合并先验（零译码选型 + 代理验证）
- 先做零译码检验：三源信道是否可以合并（跨源 held-out 对数似然、差分分布比较）。
  前提是三源 SER 同在 0.24–0.25，且 T3 已显示跨时段保真。
- 若可以合并：先验改用合并后的 TRAIN，在代理上重选 m 和 rescue。

### T-3 判决导向的先验累积（EXPLORE，代理）
- 已协调成功的块会给出精确的 (a, b) 对，而且**不增加任何泄漏**。按部署顺序把这些对逐块并入直方图，先验会越用越密。
- 同时报告：所需 TRAIN 牺牲比例能下降多少，以及对净良率（SKR 侧）的影响。
- 注意：只有经 tag 验证成功的块才能并入；一旦并入错误的块，先验会被污染。
- 这也是 MSD 重新开启的候选前提。

### T-4 多轮增量披露（EXPLORE，代理）
- NB 的 rescue 从单轮扩展到 2–3 轮，步长按期望良率优化，目标是把 FER 惩罚（0.17–0.38）转换成少量额外泄漏。
- 轮数模型要用样本外帧校准，避免隔壁 W2 那种失败。

### T-5 真实复验（DECIDE，需用户确认）
- 条件：代理预测相对 S-5 至少改善 0.10 的 f。
- 主线：在 R1 原数据上跑，标注为再检验；若 T-0 盘点出适用的干净段，同时跑一个干净 OOS 臂，单独报告。
- 门：G-1a（f ≤ 1.55），G-1 仍为目标。
