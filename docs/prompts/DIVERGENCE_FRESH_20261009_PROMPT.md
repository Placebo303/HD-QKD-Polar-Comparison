# 发散用 prompt — 全新对话，不读本仓库（2026-10-09，信息协调范围）

> 用法（用户手动执行）：
> 1. 开一个**全新**对话：不在本仓库里开，不开项目记忆，不上传项目文件。
>    不要提 LDPC、Polar、RA 码、两级方案、MSD、效率 f 这类词——那是我们现有的答案，
>    提了就锚定。
> 2. 把分隔线之间的内容原样粘贴。
> 3. 换视角再跑 2 次：把第一行「视角」换成附录里的 B、C（最好用不同模型）。
>    多个视角给出相同结论，**不等于**结论被验证。
> 4. 不要追问"哪个最好"。把每次的完整输出存下来，交给
>    `docs/prompts/DIVERGENCE_RETURN_20261009_PROMPT.md`。

---

视角：请从**有限码长信道编码理论研究者**的角度思考。

**问题**：两方 Alice 和 Bob 各自持有一串由光子到达时间导出的相关数据。他们要通过一条公开的、可认证的经典信道交换信息，让 Bob 得到和 Alice 完全相同的序列（信息协调）。目标是公开披露的比特尽量少，同时失败率可控、计算量可接受。披露的每一比特都要从最终密钥里扣掉。安全分析不在本问题范围内，只看协调本身。

**实测事实**（别的不要假设）：
- 时间轴被切成帧，帧内有 d 个时间 bin，bin 宽 bw 可以在后处理时自由选（50 ps–6.4 ns），帧长约 200 ns。Alice 的符号是她的光子落在哪个 bin，Bob 也一样。
- 两人的时间差 Δ：
  - 高斯核 σ≈17–20 ps，另有约 1–2% 的宽成分（σ 约 100 ps 量级），来源未定；
  - 3 s 内中心漂移 < 1 ps；
  - 两路之间有一个可校准的固定时延偏移，校准前约 50 ps。
- 由此得到的符号差 e = b − a（bw=200 ps 时）只取 {0, +1, −1}，逐符号近似独立：
  - 未校准：P(e≠0)≈0.24，非零时几乎总是同一个方向；
  - 校准后：P(e≠0)≈0.06，非零时两个方向约 52–61 : 39–48。
- Bob 除了 bin 编号，还知道光子在 bin 内的**精细位置**（ps 级）。按经验估计，这能把 H(A|B) 从约 0.80 降到约 0.24 bit/符号（未校准），校准后约 0.39 → 约 0.2。
- 数据形态：只有 3 s 和 10 s 的短采集，每段约 3×10⁴–10⁶ 个符号对，小批量处理。
- 研究者以软件为主，可以少量新采集。

**任务**：

1. 独立提出**至少 6 个**关于这个协调问题的科学问题，**不要排名**。要求：
   - 覆盖：编码与译码结构、信道与先验建模、协议与交互方式、问题本身的表述；
   - 至少 1 个来自分布式信源编码 / 带边信息量化（Slepian–Wolf、Wyner–Ziv 一类）的视角；
   - 至少 1 个反直觉或高风险；
   - 至少 2 个要求**改变协调问题的表述本身**，例如：协调什么、要不要全部协调、目标函数是什么。而不是把某个现成方案调得更好；
   - 任意两个问题的核心机制不能相同。
2. 对每个问题分别给出：
   - 为什么重要；它依赖哪些假设；
   - 证据 / 推测 / 未知，三者分开写；
   - 最接近的 3–5 篇原始文献：只写作者、年份、题目大意，**一律标注「待核实」，不要编造 DOI**；
   - **一个能推翻它、成本最低的计算或仿真**，以及在上述条件下能否做；
   - 如果核心假设失败，还剩多少独立价值。
3. 单独列出：你认为上面的问题描述里隐含了哪些**可能是错误的假设**，或者问错了问题的地方。
4. 不要评价能发什么期刊；不要给"最推荐"的排序；不要直接给出一个完整方案。
