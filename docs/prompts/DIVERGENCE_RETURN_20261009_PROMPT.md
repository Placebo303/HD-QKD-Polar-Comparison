# 回收用 prompt — 在本仓库里评估发散结果（2026-10-09）

> 用法（第 3 步后半，用户手动执行）：拿到 `DIVERGENCE_FRESH_20261009_PROMPT.md`
> 的 2–3 份输出后，在本仓库开一个 session，把分隔线之间的内容粘贴进去，
> 再把那几份输出原样贴在 `【外部输出】` 后面。
> 文档类工作：不执行实验，不需要 track 门。

---

必读：`AGENTS.md`、`docs/NOW.md`（含「挑战方向」节）。下面【外部输出】里是 2–3 个**没读过本仓库**的对话给出的研究问题。

**先记住一点**：你读过本仓库，所以你被现有主线（短采集到达时间 HD-QKD 的信息协调）锚定了。评估时的默认风险是：把外部方向翻译成"主线的某个改进"，或者因为它离主线远就打低分。每次你想这样做的时候，在输出里显式标出来。

**任务**：

1. **去重归类**：合并机制相同的问题。每个保留下来的问题归入一类：
   - (I) 落在本仓库近期框架内：现有数据，加上软件或少量采集；
   - (II) 同一平台，但需要新的测量类型（例如共轭基、新光源设置）；
   - (III) 长期方向，或需要别的平台。
2. **文献核查**：每个问题核查最接近的 3–5 篇原始论文。
   - 先用 sciverse，arXiv/网页只用来找最新论文；
   - 只引用检索到的论文，写 DOI；外部输出里写的文献一律视为待核实；
   - 写明每篇论文**已解决**了什么、**还没解决**什么。
3. **证据对照**：对每个问题，列出本仓库里已有的支持或反对证据（引用文件路径），以及物理或信息论约束。证据 / 推测 / 未知分开写。
4. **推翻计算**：给出成本最低的推翻计算或实验，并标注在本仓库里是 EXPLORE（零成本或合成）、DECIDE（读真实数据），还是需要新采集。
5. **最后才打分**：科学重要性 30%、实质创新性 25%、可行性 20%、可验证性 15%、长期潜力 10%。
   - 每个分数后面跟一句证据；
   - 没有证据的维度写"未知"，**不填数字**；
   - 近期（I、II 类）和长期（III 类）**分开排**，不放进同一张表比较。
6. **写回仓库**（只改文档）：
   - `docs/NOW.md` 挑战方向表：只收 I、II 类中带推翻计算的方向，全表保持 ≤ 5 行。表满时，新方向要替换掉证据最弱的一行，被替换的留墓碑。
   - 新建 `docs/DIRECTIONS_LONGTERM.md`：III 类每个方向一段，写核心问题、最接近的文献（含 DOI）、推翻实验、需要什么平台。不做排名。
   - scoped 提交，不 push。

**禁止**：
- 改主线路线或主度量。需要改的话，写成给用户的一个 DECIDE 问题。
- 为外部方向开新的执行包。推翻计算只写到表里，由用户决定什么时候做。
- 编造文献。

**返回**：
1. 归类表（I / II / III）；
2. 每个方向的核查摘要：最接近的论文、未解决的问题、推翻计算；
3. 近期和长期两张分开的打分表；
4. 挑战方向表的改动；
5. 你自己发现的锚定痕迹：哪些地方你差点把外部方向翻译回主线；
6. 提交哈希。
