# Design: Formal Nonbinary LDPC v2 Successor

## Evidence boundary and fixed identity

The sole v1 N3 confirmation is immutable non-promotion evidence: its selected margin-7, scale-1.0, max-iteration-10 policy used **32 checks in both strata** and achieved 18/32 (p=.20) and 5/32 (p=.30) verified successes. It had valid denominators and no prohibited status failures. Its official strict verification remains failed only because post-run whole-worktree-status drift made the old provenance rule unverifiable. None of its confirmation arrays, outcomes, policy, seeds, or artifacts may tune, rerun, repair, or select v2.

v2 has exact identity `nbldpc_formal_v2`, codebook canonical magic `NBLDPC2\n`, qualification-plan schema `NBLDPCQ2`, and run ID/output root `20260726_v2_nbldpc_synthetic` / `comparison_bench/outputs_comparison/formal_ir_methods/20260726_v2_nbldpc_synthetic`. It is additive. v1, `qldpc_reference`, Polar, existing outputs, and dependencies do not change.

## Exact 48x64 QC/protograph mother codebook

The new codebook is over the existing pinned polynomial-basis GF(1024), length n=64, with information columns 0..15 and parity columns 16..63. Its fixed construction seed is the non-boolean integer `2026072602`; rows and columns use ascending zero-based order. The mother has 48 rows and exact prefixes 24, 32, 40, and 48. Its canonical bytes have magic `NBLDPC2\n`, compact key-sorted ASCII header, then every 48x64 coefficient as unsigned 16-bit big-endian row-major values. Header and manifest record all values below, IDs, ranks, cycle count, and ordered prefix relation.

Let alpha be the pinned primitive field element encoded as integer 2, verified by the N0 full 1023-element multiplicative cycle. The parity block is `B = I_48 + alpha P_48`, where `P[r,c]=1` exactly when `c=(r+1) mod 48`. Thus row r contains parity coefficients 1 at column `16+r` and alpha at column `16+((r+1) mod 48)`. The verifier computes alpha^48 and requires it not equal 1; because `P^48=I`, it then proves B invertible by pinned-field elimination and requires rank(B)=48.

Information pairs use an exact deterministic K16 1-factorization, not random rejection. Its vertices are 0..14 plus 15. Round r in 0..14 contains edge `{15,r}` and edges `{(r+k) mod 15,(r-k) mod 15}` for k=1..7; every edge is stored ascending and the eight edges of a round are sorted lexicographically. Construct one Fisher-Yates permutation of rounds 0..14: for descending i=14..1, swap with `int(SHA256(ASCII("NBLDPC2|roundperm|2026072602|" + i)),16) mod (i+1)`. Take the first six rounds in that resulting order. Each is a disjoint eight-edge matching, and distinct rounds partition the K16 edges; hence the six selected rounds produce 48 unique information pairs and every information vertex has degree six.

For the selected matchings in order, enumerate rotation vectors `(a0,...,a5)` in lexicographic product order over 0..7. Rotate matching j left by aj, concatenate the six rotated matchings, and accept the first vector whose last edge of each block is disjoint from the first edge of the next block, including block 5 to block 0. The exact search bound is 8^6; exhaustion is `codebook_invalid`. Within a matching all pairs are disjoint, and the rotation condition makes every cyclic adjacent row pair disjoint. The verifier recomputes rounds, permutation, selected matchings, first valid rotation vector, concatenated pair order, and the proof; it does not sample or search a trial cap.

The two information coefficients in row r, slot s=0,1, are `1 + int(SHA256(ASCII("NBLDPC2|coef|1024|2026072602|" + r + "|" + s)),16) mod 1023`. Hence every row has exactly four nonzero edges; every information column has mother degree six; every parity column has mother degree two. Non-adjacent rows share no parity columns and cannot share two information columns; adjacent rows share one parity column but are required to share no information columns. Therefore every row pair shares at most one column and the verifier requires deterministic 4-cycle count zero. It also recomputes the 1-factorization, round permutation, selected rounds, rotation vector, pairs, coefficients, alpha order/exponent, B rank, all prefix GF(q) ranks, cycle count, canonical bytes, and hashes. A prefix with rank below its check count is `codebook_invalid`; no fallback exists.

## Exact candidate decoder variants

All candidates use q=1024, QSC p=.20/.30, Alice syndrome/Bob side information only, MSB-first mapping, and separate locked Toeplitz verification/accounting. The four canonical candidate IDs are:

1. `nbldpc_formal_v2_control_n1_flooding`: v1 N1 matrix plus flooding FFT-QSPA;
2. `nbldpc_formal_v2_qc48_flooding`: the new codebook, flooding FFT-QSPA;
3. `nbldpc_formal_v2_qc48_damped_l050`: new codebook; after each normalized check-to-variable message `u`, set `c_new=.5*u+.5*c_old`, then normalize;
4. `nbldpc_formal_v2_qc48_damped_l050_tempered_t080`: candidate 3, except first replace normalized `u` by `u_i^.8 / sum_j u_j^.8`, then apply the same .5 damping and normalize.

Candidate 4 is meaningful because componentwise tempering changes relative likelihood ratios before damping; it is not a scalar that normalization cancels. Directed check messages initialize uniformly. Float64 only; nonfinite/zero normalizers fail `decoder_error`. No EMS/list pruning, external decoder, per-frame adaptation, Alice truth, or truth-based stopping is permitted.

Each accepted v2 prefix has row weight four. With 48 checks, 192 edges, q=1024, the declared dense storage is `(2*64 + 2*192)*1024*8 = 4,194,304` bytes; the fixed cap is 16 MiB. The domain cap is n=64, checks<=48, row weight=4, q=1024, max_iter<=20. A decoder call cap is 20 seconds; complete single-process execution cap is 21,600 seconds; workers=1. Exceeded caps are retained `aborted_resource_limit`.

## Fresh synthetic contract and selection

Development seed roots are p=.20 `202607340000` and p=.30 `202607350000`; confirmation roots are p=.20 `202607360000` and p=.30 `202607370000`. Frame i uses root+i in its recorded PCG64 generator. These roots are disjoint from v1's 202607300000/310000/320000/330000 roots. There are 24 sacrificed development frames per stratum and 32 immutable confirmation frames per stratum. Each frame uses v1's exact Alice/QSC call order; all arrays, atomic keys, frame seeds, and role/stratum/index identifiers are hashed and must have zero overlap.

For every development frame, each candidate runs each global policy in candidate-major, margin-major, iteration-major, p-major, index-major order. Margins are {0,4,8}; maximum iterations are {10,20}; QSC prior is exactly nominal p. For p, `needed=ceil(64*(h2(p)+p*log2(1023))/10)+margin`, with `h2(p)=-p log2 p-(1-p)log2(1-p)`. The control candidate may choose only the verified v1 prefixes (16,24,32); each QC48 candidate may choose only (24,32,40,48). Each chooses its smallest permitted prefix at least needed, otherwise retains `unsupported_domain`. The canonical policy hash therefore includes candidate ID, its ordered permitted prefixes, and its per-stratum selected check counts.

A development policy is ineligible if any of its outcomes is `syndrome_inconsistent`, `decoder_error`, `unsupported_domain`, `codebook_invalid`, `invalid_run`, or any status outside the allowed retained decoder outcomes. `decode_failed`, `verify_failed`, and `aborted_resource_limit` are retained performance failures and do not by themselves make a policy ineligible. Among eligible policies, selection maximizes the **minimum** of the p=.20 and p=.30 verified-success counts, then total verified successes, then minimizes total key-dependent disclosure and total iterations, then takes lexicographically smallest candidate-policy SHA256. If no eligible policy exists, selection is exactly `{"selected_policy":null,"selected_policy_sha256":null,"selection_key":null,"reason":"no_eligible_policy"}`; readiness is false, run status is `non_promoted_development`, and confirmation is neither generated nor executed.

Confirmation is executed only if the selected policy has at least 22/24 verified successes in each development stratum. This 91.7% readiness floor is deliberately below, but close to, the 31/32 (96.875%) confirmation standard: it avoids spending immutable confirmation evidence on plainly inadequate candidates without claiming promotion. Failure is `non_promoted_development` and confirmation is not generated/executed. Confirmation never enters candidate/policy selection.

The Toeplitz input is 640 bits and tag length 64, so every fresh CSPRNG record has exactly 703 bits. Development has 4*6*48=1152 unique seed records; confirmation has 64. All seed IDs must be unique, disjoint from locally discoverable formal plans, and bound to candidate-policy-frame (development) or selected-policy-frame (confirmation). A 48-check syndrome discloses exactly 480 key-dependent bits; an invoked tag adds 64; seed bits are public control and separate.

## Artifacts, verifier, and N4 gate

Artifacts are exactly `pre_run_plan.json`, `formal_frame_outcomes.csv`, `formal_transcript.jsonl`, `formal_run_manifest.json`, `formal_codebook_manifest.json`, `formal_candidate_manifest.json`, `formal_policy_manifest.json`, and `formal_qualification_report.json`. Statuses are `verified_success`, `verify_failed`, `decode_failed`, `syndrome_inconsistent`, `aborted_resource_limit`, `decoder_error`, `unsupported_domain`, `codebook_invalid`, `invalid_run`, and `non_promoted_development`; all requested confirmation failures stay denominator-included.

Promotion requires 31/32 verified successes independently in each confirmation stratum, full denominators, zero prohibited integrity failures, exact transcript/accounting reconciliation, and a valid hash DAG. Otherwise it is non-promoted; no rerun or confirmation tuning is allowed. The plan binds SHA256 hashes of the exact qualification modules, CLI, candidate manifest, generator contract, and verifier. Commit/dirty state and live worktree state are recorded, but only scoped bindings gate verification; unrelated later worktree drift is diagnostic.

Only synthetic promotion may authorize planning of a separate N4 read-only adapter from existing Polar sidecars (`a_eff.npy`, `b_eff.npy`, metadata) to locked q=1024 frames. This change shall not process raw `.ttbin` or real sidecars, rerun Polar, alter sidecars, infer channel parameters from Alice truth, or make real-data claims. An N4 runner, lock, verifier, and explicit pre-execution authorization remain required.
