# Design: Improve Formal LDPC v2

## Evidence Boundary

The v1 synthetic package remains immutable diagnostic evidence. V2 uses fresh
run IDs, seeds, plans, manifests, and output roots. Calibration, screening,
selection, and confirmation are separate phases with hashes binding every
input and decision.

## Short-Term Lane: Decoder and Rate Margin

Reuse the installed `ldpc==2.4.1` and formal transcript/verification contract.
Do not add a decoder dependency.

The development grid is exactly nine global policies:

- `rate_margin` in `{0,1,2}`;
- decoder in `{("OSD_0",0), ("OSD_CS",1), ("OSD_CS",2)}`.

`OSD_1` is not a valid `ldpc==2.4.1` method name. `OSD_E` and BP+LSD are
excluded from v2 to keep the pre-registered grid bounded. Exact constructor
probes for all three included pairs are required before development execution.

The ordered rates are
`[r050,r0375,r025,r0125]`. For each calibrated plane:

`base_index = index(select_rate(p_hat))`

`effective_index = min(base_index + rate_margin, 3)`

The selected rate is `ordered_rates[effective_index]`. Thus a larger margin
always adds checks and never reduces disclosure. The existing `select_rate`
boundaries remain unchanged. Calibration rejects empty counts, non-finite
`p_hat`, or `p_hat` outside `[0,.5)`; `p_hat=0` is clamped to `1e-4` only for
the decoder's channel parameter, not for rate selection.

Every canonical policy contains:

- rate margin and decoder method/order;
- BP schedule remains serial with explicit order `[0..63]`, one OMP thread,
  `minimum_sum`, scaling 1.0, and `max_iter=50`;
- `policy_id = SHA256` of UTF-8 compact sorted-key JSON over the policy without
  the `policy_id` field.

The nine-policy grid is run only on the existing synthetic calibration batches,
which are sacrificed and excluded from confirmation. One global policy across
both p strata and all planes is selected by deterministic ordering: maximize
total verified successes, then minimize total key-dependent disclosure, then
minimize the frozen decoder complexity rank
`OSD_0/0=0, OSD_CS/1=1, OSD_CS/2=2`, then lexical `policy_id`. Runtime in
integer nanoseconds is retained as a diagnostic but never participates in
selection, because machine load must not alter the selected policy.
Confirmation receives only that frozen policy. Unsupported backend options
are recorded, never silently substituted.

The v2 runner is new and does not branch inside the v1 runner. Its exact
top-level artifacts are the six formal v1 names plus
`formal_policy_manifest.json`. The policy manifest contains the nine canonical
policies, constructor-probe results, every sacrificed frame outcome, aggregate
selection tuple, selected policy, calibration hashes, and a v1 golden-hash
snapshot. The run manifest hashes the plan, outcomes, transcript, codebook
manifest, and policy manifest. The qualification report stores the run-manifest
hash. This one-way DAG covers all seven artifacts without a circular hash.

## Medium-Term Lane: n=64 Nested Code Family

Keep HGF2V1 canonical bytes and check counts `{32,40,48,56}`. For each plane,
generate exactly 16 deterministic 56x64 master candidates. Rate matrices are
the first 32/40/48/56 rows of one master, so every selected plane family is
nested/rate-compatible. Seeds are derived from compact domain bytes containing
generator ID/version, plane and candidate ID; no runtime entropy is used.

Each prefix must have full row rank and pass structural validity:

- no zero or duplicate columns;
- row weights in `[2,8]` and column weights in `[1,4]`;
- exact 4-cycle count;
- exact syndrome-collision counts for all weight-1 and weight-2 error vectors;
- exactly 64 fixed probe errors per rate: 32 weight-1 and 32 weight-2 vectors
  generated by PCG64 from a separately domain-separated public seed.

A candidate invalid at any prefix is excluded for the whole plane. Select one
master candidate per plane using one lexicographic score summed across all four
prefixes: maximize probe errors whose syndrome is unique within the exhaustive
weight-1/2 error universe; minimize weight-1/2 syndrome
collisions; minimize 4-cycles; minimize maximum row weight; then smallest
candidate ID. Do not set empirical thresholds after observing confirmation.
This screening stage does not run a decoder and SHALL NOT call this structural
proxy a decoded or verified success. Only formal Toeplitz-qualified outcomes
may use `verified_success`.

Persist every candidate's generator/version/seed, per-prefix structural
metrics, probe-vector hash, probe results, selected flag, canonical prefix
hashes, and selection-policy hash. Only the ten selected master families
(40 prefix matrices) enter a fresh formal codebook. This is
`protograph-inspired`/rate-compatible engineering, not a claim of reproducing
TBPRL codes.

The codebook screening set is separate from both v2 development calibration
and v2 confirmation. The final selected codebook is frozen before the nine
policy grid runs; neither synthetic nor real confirmation may change it.

## Promotion Sequence

1. Unit and contract tests.
2. Materialize and verify the screened nested codebook.
3. Run the nine-policy sacrificed development grid and freeze one policy.
4. Fresh synthetic confirmation with the existing p=.01/.02 strata and
   at least 31/32 verified successes per stratum.
5. Only after synthetic promotion, create a fresh real lock and require 60/60
   verified successes in the locked domain.
6. Only then may a separate OpenSpec authorize frame-identical
   Cascade/LDPC/Polar comparison.

## Fresh Synthetic v2 Qualification Lock

The first attempted v2 synthetic ID,
`20260725_v1_ldpc_v2_synthetic`, is invalid integration evidence. Its plan and
seven run artifacts are immutable. All 576 development and 64 confirmation
calls returned `unsupported_domain` because `ldpc_formal_v2` incorrectly used
the v1 codebook verifier, which rejects v2 filenames/matrices. Verification was
never invoked. Add only `invalid_run_notice.json` with the exact artifact
hashes, observed counts, cause, and fresh successor; do not overwrite or reuse
its frames, deterministic seeds, or 640 CSPRNG seeds.

The only next runnable v2 synthetic ID is
`20260725_v2_ldpc_v2_synthetic`. The CLI requires an explicit fresh
`--output-dir`; it has no default output path and refuses a nonempty directory
except its own exclusively-created `pre_run_plan.json`.

The plan freezes:

- dimension 1024, gray mapping, 64 symbols/frame;
- one Alice `PCG64(2026072651)` stream consumed sequentially for four batches
  in this exact order: calibration p=.01 (32), calibration p=.02 (32),
  confirmation p=.01 (32), confirmation p=.02 (32);
- independent BSC PCG64 seeds `2026072661..2026072664` in that same order;
- development order `PCG64(2026072671)` over the 64 calibration frame IDs and
  confirmation order `PCG64(2026072672)` over the 64 confirmation frame IDs;
- 576 pre-materialized system-CSPRNG Toeplitz seeds, one for every
  `(policy_id, development_frame_id)`, and 64 independent confirmation
  Toeplitz seeds; none is generated during execution;
- the deterministic screening-manifest hash, selected-codebook manifest hash,
  nine-policy hashes, dependency/source/git/environment provenance;
- five seconds per method call and 30 minutes for the complete run.

The rate calibration for each p stratum uses only its 32 sacrificed calibration
frames. Every one of the nine policies runs all 64 calibration frames; all
attempted statuses remain in the policy manifest. The globally selected policy
is written and hashed before the first confirmation call. Confirmation runs
exactly its 64 frames once.

The exact seven artifacts are:

1. `pre_run_plan.json`
2. `formal_frame_outcomes.csv` (confirmation only)
3. `formal_transcript.jsonl` (confirmation event bytes)
4. `formal_codebook_manifest.json`
5. `formal_policy_manifest.json` (all development outcomes and selection)
6. `formal_run_manifest.json`
7. `formal_qualification_report.json`

The runner uses an exclusive-write failure finalizer. A partial or failed run
is retained as non-promotion evidence and never resumed by overwriting bytes.
A separate `--verify` path is read-only and reconstructs generation/order,
calibration, screening/codebook/policy hashes, seed binding, transcript groups,
disclosure totals, status denominators, and the two 31/32 gates.

V2 codebook validation is independent of v1. Each entry must match the v2
filename, canonical HGF2V1 bytes/hash/rank, selected master candidate and exact
rate prefix in the screened manifest. `ldpc_formal_v2` SHALL NOT call
`ldpc.verify_codebook_entry`; v1 golden hashes remain a separate regression
snapshot only.

## Stop Conditions

Stop and return to OpenSpec if the pinned backend cannot expose a deterministic
stronger decoder, the candidate family cannot satisfy rank/structural checks,
or the requested promotion would require confirmation-set tuning.
