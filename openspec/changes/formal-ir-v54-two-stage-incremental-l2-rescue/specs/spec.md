## R4. Leakage and conditional disclosure — 三阶段

Tag SHALL 为 `compute_tag_64(empty_uint8,x2)` L2-only。泄漏 SHALL 冻结：`leak_base=5*m2+80+64`；`leak_stage1=5*(m2+8)+80+64 = leak_base+40`；`leak_stage2=5*(m2+16)+80+64 = leak_base+80`。`leak_stage1 - leak_base =40` 且 `leak_stage2 - leak_stage1 =40` 恒。Summary SHALL 承诺报告：`first_pass_success_leak = leak_base (1064/1094/1104)`；`stage1_success_leak = leak_stage1 (1104/1134/1144)`；`stage2_leak = leak_stage2 (1144/1174/1184)`（stage2 成功与最终失败同为 `leak_stage2`）；`per_source_avg[s]=leak_base[s]+40×N_stage1_attempted[s]/15+40×N_stage2_attempted[s]/15`（`N_stage1_attempted[s]=count(!verify_base) per source`，`N_stage2_attempted[s]=count(!verify_base && !verify_stage1) per source`）与 `overall_avg=(Σ leak_base[source(block)]+40×N_stage1_total+40×N_stage2_total)/45`（`N_stage1_total=count(!verify_base)` overall，`N_stage2_total=count(!verify_base && !verify_stage1)` overall，因三源 `leak_base` 不同禁止用单一 `leak_base+40N/45` 当 overall）；`failed_conditional_leakage = leak_stage2`；`avg_disclosure_per_attempted_frame = overall_avg /1024` bits/symbol 描述性（per source 分层）；`total_disclosed_bits = Σ leak_total`（45块求和）与 `disclosure_per_final_exact_block=total_disclosed_bits/final_exact_full_count`（`final_exact_full_count==0` 则 `null`，删除含糊 `final_accepted_bits`）；`f_avg = avg_leak / [1024×(H(U1|B)+H(U2|U1,B))]`（若保留则分母为 `1024×信息熵和`，禁 `N_blocks×(H1+H2)`）描述性。仅 `first_pass_success` 帧 SHALL NOT 增加至 `stage1` 泄漏；仅 `stage1_success` 帧 SHALL NOT 增加至 `stage2` 泄漏；`stage2` 成功与最终失败均 SHALL 计 `leak_stage2`。`V53 33/45` 仅历史描述。

## R5. Three-pass conditional protocol（verification-only，二阶段嵌套）

每块 SHALL 执行：`base = decode(H_base, P(U2), s_base)` → `verify_base = syndrome_ok_base && tag_ok_base`；该一次确定性译码为首阶段起点；若 `verify_base` 则停，`final_exact=exact_base`，`leak=leak_base`，`used_inc1=False, used_inc2=False`；否则 `s_inc1 = H_inc1 * u2_true`，`s_joint1=[s_base;s_inc1]`，`stage1 = decode(H_joint1, P(U2), s_joint1)` → `verify_stage1`，若 `verify_stage1` 则停，`final_exact=exact_stage1`，`leak=leak_stage1`，`used_inc1=True, used_inc2=False`，`stage1_rescued = (verify_stage1 && exact_stage1)`；否则 `s_inc2 = H_inc2 * u2_true`，`s_total=[s_base;s_inc1;s_inc2]`，`stage2 = decode(H_total, P(U2), s_total)` → `verify_stage2`，`final_exact=exact_stage2`，`leak=leak_stage2` 无论成功/失败，`used_inc1=True, used_inc2=True`，`stage2_rescued = (verify_stage2 && exact_stage2)`。`exact_*` SHALL 为 oracle `array_equal`，`tag_ok` 为真实 L2-only 哈希验收；公开成功以 `tag_ok` 判，`exact` 仅 oracle 统计但两者均报告；**触发仅 verification**，`exact` 不触发。每块 `L1 1+base 1+stage1 ≤1+stage2 ≤1`，总 `45 L1+45 base+≤45 stage1+≤45 stage2=90-180 硬帽180 (L2 45-135)`。`N_stage1_attempted=count(!verify_base)` overall，`N_stage2_attempted=count(!verify_base && !verify_stage1)` overall，per source 分别 `N_stage1[s]` 与 `N_stage2[s]`。

## R6. Fresh held-out 45 blocks — 剩余窗口枚举分散选择（排除 V53 后）

Workload SHALL 为 `45` fresh held-out 块的三阶段条件确认：每块共享 `L1`，`base` 1次 → 条件 `stage1`（仅 `!verify_base`）→ 条件 `stage2`（仅 `!verify_base && !verify_stage1`），同 `bob` 同 prior (TRAIN)，同 `H1`。Held-out 区间 per source `H=400/554/729, base=1600/2213/2916`，枚举 `all_starts=0..H-4` 的 `[s,s+3]` 四帧窗口，过滤与已用区间 `U2`（V48 45区间 + V50 15 + V51 15 + V52 15 + V53 45 =135区间540帧）重叠者得 `S2` 按 `ordinal` 排序 `K2=|S2|≥15`，以 `index_j=floor(j*(K2-1)/14) j=0..14` 分散选择 15/源，建议 block IDs `395001-015/395101-115/395201-215` 仅标识（真实以 `frame_ids=[base+s .. base+s+3]` 为准），每块写死 `held_out_ordinal_start/end`、`frame_ids[4]`、`pairs_count=1024`、`sampling_mode=deterministic_four_consecutive_frames_heldout_fresh_v54`、`BLOCK_LENGTH=1024`。SHALL 与已用 `V48-V53` 的 `frame_ids` 零重叠 per source 可机械校验，且最终 45 块两两非重叠（gap≥4），否则 `REGISTRY_INVALID`。SHALL NOT 复用已用帧、SHALL NOT 用 outcomes 选块。门禁不因 V53 差两个改阈值。

## R7. Reporting promises — SHALL（explicit，三阶段）

Summary SHALL 显式包含（overall 与 per-source 1M/1p5M/2M）：`base_exact_full_count` 与 `verify_base=count(syndrome_ok&&tag_ok)` 分别计数（禁止假定相等），`stage1_exact_full_count` 与 `verify_stage1` 分别，`final_exact_full_count` 与 `verify_final` 分别，`stage1_rescued_count` 与 `stage2_rescued_count`，`N_stage1_attempted=count(!verify_base)` 与 `N_stage2_attempted=count(!verify_base&&!verify_stage1)`（overall & per-source），`rescue_rate_stage1 = stage1_rescued/N_stage1_attempted` 与 `rescue_rate_stage2 = stage2_rescued/N_stage2_attempted`（禁止用 `45-base_exact` 作分母）描述性；`per_source` 分层；`first_pass_success_leak (leak_base)`，`stage1_success_leak (leak_stage1)`，`stage2_leak (leak_stage2, 成功与失败同)`，`per_source_avg[s]=leak_base[s]+40×N_stage1[s]/15+40×N_stage2[s]/15` 与 `overall_avg=(Σ leak_base[source(block)]+40×N_stage1_total+40×N_stage2_total)/45`（因三源 `leak_base` 不同禁单一 `+40N/45` 当 overall），`avg_disclosure_per_attempted_frame (=overall_avg/1024)`，`total_disclosed_bits (=Σ leak_total)` 与 `disclosure_per_final_exact_block=total_disclosed_bits/final_exact_full_count`（`final==0` 则 `null`，删除含糊 `final_accepted_bits`，`f_avg` 若保留分母 `1024×(H(U1|B)+H(U2|U1,B))` 禁 `N_blocks×(H1+H2)`），`failed_conditional_leakage (leak_stage2)`，`f_avg/f_failed`；`joint1_rank==m2+8`，`total_rank==m2+16`，`nested_stage1==True`，`nested_stage2==True`，`independence_1==8`，`independence_2==8`，`row_degree_max≤16`，`E_inc1/E_inc2`；`real_tag_acceptance (tag_ok rate per stage)`；`reclassified 四类 exact/detected/decoder_non_syndrome/undetected`；`paired base vs stage1 vs final` per block（`Δexact_stage1 = stage1 - base`, `Δexact_stage2 = final - stage1`, `Δexact_total = final - base`，McNemar `b/c` 仅描述）；`iterations/runtime/residual` 分布；`stage1_attempt_rate=N_stage1_total/45` 与 `stage2_attempt_rate=N_stage2_total/45`。`V53 33/45` 仅历史描述，不作门禁依据。以上 SHALL 在 proposal/design/tasks/specs 中显式承诺且在 summary 中兑现。

## R8. Primary gate — 四终态

Gate SHALL 为：`EVIDENCE_INVALID` 优先若完整性/守卫/秩/嵌套/重叠/记账失败；否则若 `final_exact_full ≥35/45 (77.78%) ∧ 每源≥10/15 (66.7%) ∧ undetected_accepted_wrong==0 (G3') ∧ joint1_rank==m2+8 ∧ total_rank==m2+16 ∧ nested_stage1 && nested_stage2 ∧ 记账90-180硬帽且每块L1 1+base1+stage1≤1+stage2≤1 ∧ 45 fresh块与已用零重叠`，则细分：
- 若 `stage1_exact_full ≥35/45 ∧ 每源≥10/15 ∧ undetected==0` → `V54_DELTA8_ALREADY_SUFFICIENT`
- 否则（`stage1` 未过但 `final` 过）→ `V54_DELTA16_ADDED_VALUE_SIGNAL`
否则若完整性通过但未满足 `final` 门禁 → `V54_DELTA16_INSUFFICIENT`。
门禁 `35/45 & 10/15 & undetected==0` SHALL 不因 V53 差两个改阈值（V53 `33/45` 仅历史描述）。不加复杂终态。`ALREADY_SUFFICIENT` 与 `ADDED_VALUE_SIGNAL` 均属 `development confirmation` 通过类，但语义区分 `Δ8 已足` vs `Δ16 增量有价值`；`INSUFFICIENT` 为未过类。
