After P1 arithmetic acceptance, implementation-only P2 builds conditional bit-prior tables and a soft-syndrome adapter boundary. It invokes no decoder and establishes no performance. Tables keep Bob's complete natural symbol as the column key; Alice bit labels use the declared natural/Gray bijection and complete order. Unobserved Bob/prefix combinations return an explicitly flagged uninformative prior rather than invented certainty. The receiver's prior-query API has no Alice truth argument.

The syndrome interface separates sender-only Alice symbols from receiver-only Bob symbols/public syndromes. Each recovered stage supplies the next prefix, including wrong syndrome-satisfying prefixes; no oracle prefix is available. Actual transmitted parity rows are disclosure bits, independent of matrix rank. The receiver requires an explicit decoder factory; executed tests use fake factories only. A separately selected lazy backend factory has an explicit iteration budget and is not invoked at this implementation milestone. Caller-owned sparse matrices keep code construction/rate selection outside this boundary. Syndrome satisfaction does not establish tag acceptance, exact decoding, FER or expected yield.

The next implementation-only construction candidate is H=[A|T], where T is a square lower-bidiagonal accumulator with unit diagonal. Its rows are independent over GF(2) by construction; no dense long-block rank elimination is required. Information columns have an explicit caller-specified degree; greedy balanced placement avoids shared row-pair four-cycles when possible and reports unavoidable fallbacks. This is a repeat/accumulate-family structural candidate, not an optimized near-capacity code. Row count and degree are caller parameters, not automatically inferred from zero TRAIN entropies. Sparse construction and fixed structural tests do not authorize a decoder experiment or accept FER/f. Stage allocations, practical code gap, calibrated-model sample availability and cost remain unresolved.

An opt-in exact-prior branch may bypass backend construction only when every queried p_error is exactly zero. The receiver then retains the MAP base, performs the same public-syndrome check and early stop, and counts the unchanged upfront disclosure. Any positive or unsupported prior retains the ordinary explicit factory path. This is a new receiver mechanism under the empirical model, not a bit-identical BP speed claim; default behavior stays unchanged. It makes no statement that finite TRAIN determinism generalizes to OOS and never changes stage row allocation or accepts a block without verification.

A separately explicit, default-disabled mixed-stage conditioning mechanism fixes exactly zero-probability error variables at zero and sends H's remaining columns and nonzero equations to the selected factory. Under this model, H e=delta reduces exactly to H_active e_active=delta; a removed zero equation with nonzero delta is inconsistent and must stop. Stored CSR zeros are eliminated on a copy before finding structurally zero rows. Returned active errors are scattered back before the unchanged original-H syndrome check. Every original transmitted row is still charged. No-equation positive variables retain MAP choices, not certainty. This mechanism includes the all-fixed case when enabled; the earlier flag retains its own behavior when mixed-stage conditioning is disabled. It makes no OOS or BP-equivalence claim.

Saved-summary error-allocation diagnostic: for positive information-density variances, minimize the unrounded/unclipped normal backoff sum sqrt(V_k)*Phi^-1(1-epsilon_k), with total epsilon=0.01. The strictly convex upper-tail objective gives sqrt(V_k)/phi(z_k)=lambda; a common sqrt(N) does not change allocation. Zero-variance terms receive zero epsilon only within this idealized objective when positive terms exist; this does not imply zero FER or disclosure. All-zero variance retains uniform allocation as a convention. Compute ceil/clipped costs separately, retaining possible worsening after discretization. No practical rate optimum, OOS guarantee or decoder execution follows. Keep P1 historical outputs unchanged; use only its previously accepted saved scalar summary and additive diagnostic roots.

Normal-tail interface correction after the diagnostic batch uses -Phi^-1(epsilon) directly to avoid floating-point cancellation in 1-epsilon. This is mathematically identical to the upper-tail quantile, not a changed objective or probability assumption. Fixed interface tests and independent review follow; existing J artifacts retain their pre-correction provenance, and no further J batch run is authorized by this implementation-only correction.
